# Sample logs - the SkyDesk demo set (synthetic)

> **Everything in this folder is synthetic.** It was generated by `scripts/generate_sample_logs.py` (seed `7`, stdlib only). No real customers, bookings, cards or e-mail addresses. "SkyDesk Airways" is a made-up airline.

One curated demo set: **16 runs of SkyDesk, an airline customer-service agent, each telling a different story** - clean successes, human-in-the-loop hand-offs done right, and every failure the analyzer looks for. 5 of the 16 runs are verified successes.

| file | what it is |
|---|---|
| `demo_agent_runs.log` | **Upload this one.** The 16 runs as plain Python `logging` lines (`agent_run key=value`), 336 agent lines plus 3 unrelated app lines (uvicorn, httpx, ...) that the app skips and counts. |
| `demo_agent_runs.jsonl` | The same 16 runs in ARL JSONL, the canonical format (`docs/LOG_FORMAT.md`). |
| `skydesk_policy.yaml` | SkyDesk's rules: verify before money moves, refunds capped at the fare paid, injection patterns, cases that must go to a human. |
| `shopdesk_policy.yaml` | The rules of ShopDesk, the second synthetic agent the success model is trained on. |

Small files in every other format (OpenAI messages, OpenTelemetry, OTLP, CSV, Langfuse) are in [`../examples/`](../examples/).

## Demo in 60 seconds

1. Start the app: `.venv/bin/streamlit run app.py --server.port 9003` and open <http://localhost:9003>.
2. **Step 1**: click **Upload** and choose `sample_logs/demo_agent_runs.log` (or pick it under *...or try a sample*).
3. **Step 2**: choose **SkyDesk policy**.
4. Click **Run analysis** and read the Summary, Action items and Run detail tabs.

Start with **`sky-0904-0028`**: the customer asked to change the phone number on the booking, `update_contact` failed three times in a row, and the agent still told the customer it was updated.

The analysis does not read it.

## Policy file format

A policy tells the analyzer *your* agent's rules. Every key is optional; missing keys fall back to the generic default. Full reference: `docs/POLICY_FORMAT.md` (also in the app: Step 2 -> *What should a policy look like?*).

| key | type | meaning |
|---|---|---|
| `name` | text | Label shown in the report. |
| `money_tools` | list of tool names | Tools that move money (refunds, credits, payments, fee waivers). |
| `money_tool_patterns` | list of regexes | Same, matched against tool names (e.g. `refund`, `payment`). |
| `contact_tools` | list of tool names | Tools that change where money, goods or messages go (e-mail, phone, address, payee). |
| `escalation_tools` | list of tool names | Calling one of these means the case was handed to a human. |
| `verify_tool_patterns` | list of regexes | Which tools count as identity verification (default: `verify`, `authenticat`). |
| `require_before` | map tool -> list | Prerequisites that must have SUCCEEDED earlier in the same run, e.g. `issue_refund: [verify_customer]`. |
| `forbidden_tools` | list of tool names | Tools the agent must never call. |
| `max_tool_retries` | integer | How many back-to-back re-tries of a failing tool are allowed before it counts as a retry loop. |
| `max_failed_verifications` | integer | After this many failed verifications the agent should escalate. |
| `injection_patterns` | list of regexes | Instruction-like text in user messages/attachments; acting on it with a money or contact tool = obeyed prompt injection. |
| `escalate_if_text_matches` | list of regexes | If the customer's text matches, the case must go to a human and no money may move. |
| `caps` | map tool -> {arg, max, min, max_from} | Numeric limits on a tool argument; `max_from: <tool>.result.<field>` caps it at a value an earlier tool returned. |

## Need more data?

The generator is deterministic and writes larger sets on demand into the git-ignored `build/samples/`:

```bash
make samples        # 300 SkyDesk runs in every format + an unlabeled copy + 600 ShopDesk training runs
make train          # retrains the success model (generates the ShopDesk training set if needed)
```

Regenerate this folder: `python scripts/generate_sample_logs.py` (seed 7).
